# Step 3C 后续练习：有限重试与指数退避

## 要解决的问题

Step 3C 证明了 API 故障能够安全结束 Agent。本练习让暂时性故障有恢复机会，
同时限制尝试次数，避免无限循环。

## 当前规则

- `request_llm(client, max_attempts=1, **kwargs)` 默认保持一次尝试；次数包含首次调用。
- Agent 显式设置 `MAX_LLM_ATTEMPTS = 3`，并用 `OpenAI(max_retries=0)` 关闭 SDK 重试。
- 超时、网络错误、限流可以重试；认证错误、其他 API 状态错误和通用 API 错误立即结束。
- TypeError 等编程错误继续向上传播。
- 等待从 1 秒开始翻倍，单次最多 8 秒；最后一次失败后不等待。
- 返回值仍是 `(response_or_none, duration_ms)`，耗时覆盖所有尝试和等待。

默认 Agent 的失败时间线：尝试 1 → 等 1 秒 → 尝试 2 → 等 2 秒 → 尝试 3 → 结束。
这限制的是尝试次数，并不是整个任务的总时间；每次请求自身仍可能花费较长时间。

## 为什么放在请求层

Agent → request_llm（内部重试）→ SDK（禁用内部重试）。

重试同一次请求时继续使用相同参数，包括 previous_response_id 和工具输出。
循环不会回到工具执行阶段，所以不会因为本地重试重新运行已完成的工具。
这不保证服务端只处理一次请求：超时可能发生在服务端已经处理请求之后。

`llm_calls` 仍表示逻辑请求数量。例如首次成功、后续失败后恢复：
逻辑请求数为 2，SDK create 调用次数为 3。性能输出已注明该区别。

## 本阶段边界与思考

本练习仅实现基础策略，尚未区分 429 的配额耗尽与临时限流，也未处理 Retry-After、
随机抖动、5xx 重试或整个任务的截止时间；这些是后续可以单独学习的内容。
