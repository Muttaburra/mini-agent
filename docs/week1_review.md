## Agent 与普通 LLM API 调用的区别

普通调用通常是输入到输出的一次转换；本项目 Agent 在模型输出后判断工具请求，执行受控副作用，再将结果送回模型，直到终止或触发预算/错误条件。

关键差异是应用拥有执行闭环：协议关联、工具授权边界、状态与资源预算都由 Runtime 负责。模型提出行动不代表它获得了执行权限。多轮对话本身也不自动等于可靠的 Agent。

## Runtime 的基本组成

1. 输入与模型接口：发送任务、instructions、工具定义。
2. 协议处理：解析调用、关联 call_id 和 previous_response_id。
3. 工具执行：白名单路由、参数验证、受限 IO。
4. 控制机制：状态转换、最大轮数、重试和错误结果。
5. 可观测性：日志、耗时与次数；当前尚缺完整事件轨迹。

相对于 C++，类型注解不是编译期参数约束，JSON 输入必须显式检查；异常边界类似在 RPC 服务入口转换错误；客户端资源所有权由 CLI 或外部调用方负责。

## 手写循环的优点与代价

优点是控制流直观，能看清模型响应如何成为工具执行；依赖少，协议与状态可逐项测试。小规模项目容易定位调用次数、轮数边界和错误传播问题。

代价是需要自己维护协议边界、工具注册一致性、重试策略、事件流和恢复语义。当前模块全局配置不适合直接扩展为多租户服务。引入框架前应先明确所需能力，框架本身不能替代安全策略和业务验收。

## 测试发现与修复

- 导入 Agent 原本会创建客户端并执行任务：Day 6 改为受保护的 CLI 入口与可注入客户端的函数。
- `calculate` 原本允许字符串相加和布尔值参与计算：补充显式类型验证，直接调用也受保护。
- 空答案、结构缺失和无效调用标识可能误判完成或崩溃：增加响应结构校验并返回 model_incomplete。
- 工具内部异常原本覆盖不完整：在执行边界转成明确失败 payload，记录 tool_errors；仍需区分内部 bug 与业务失败。
- Day 6 重构曾误改枚举成员名，三个轮数边界用例捕获该回归并修复；这是重构引入的问题，不归因于原实现。
- `completed` 语义得到澄清：表示对话结束，不是业务目标验收通过。

Day 7 首次复测没有失败；本次没有为了绿色测试放宽断言。清理演示代码后再运行全套回归。

## 尚未解决的问题

- 阶段网络超时不限制总执行时间；工具没有取消和独立超时，单轮调用数量没有预算。
- 5xx 不重试；缺少 Retry-After、抖动和配额类 429 分类；请求耗时不等于费用计量。
- 路径检查并非完整沙箱，有 TOCTOU/硬链接等边界；read_file 无大小限制，搜索对坏文件不能逐项容错。
- 错误消息可能包含本机信息，工具输出需考虑脱敏和可序列化契约；算术未限制 NaN/Infinity。
- 客户端初始化、非 SDK 编程错误可能直接抛出；CLI 失败退出码未形成稳定契约。
- 模型、注册表、工作目录含全局配置；没有数据库、任务历史、用户审批、恢复、多用户隔离或线上评估集。

## Week 2 优先重构三个地方（建议，未实施）

### 1. Runtime 与每次任务配置隔离

保留函数入口，注入 RunConfig、ToolContext 与注册表，消除通过修改全局工作目录切换用户的需求。CLI、未来 GUI/FastAPI 使用同一核心。验收应包含两个不同工作区的任务互不影响。

### 2. 结构化执行事件和错误契约

增加稳定 run_id、步骤/工具事件、请求尝试统计及脱敏错误类型，分开“对话终止”与“业务验收”。先用内存事件收集器验证，再接数据库；GUI 不应解析日志文本判断进度。

### 3. 副作用、预算与恢复边界

设计总时间/工具次数/读取大小预算、取消入口、具体动作审批及幂等策略。对“文件写成功但结果未记录”的故障建立对账测试，再谈自动恢复，避免重放副作用。

数据库建议保存任务元信息、状态与时间、模型响应关联、脱敏工具调用及结果引用、审批和检查点；不保存密钥。GUI、数据库、FastAPI、LangGraph、MCP 均留待后续评估，当前没有实现。

## Git 交付方式

本次只准备本地改动，不自动 commit 或 push。建议提交信息：

```text
docs: finalize Mini Agent CLI v0.1 handoff and architecture review
```

从根目录检查并提交：

```powershell
git diff --check
git diff --stat
git diff
git add README.md .gitignore tool_impl.py tool_schema.py logging_demo.py docs/architecture.md docs/week1_review.md
git diff --cached --check
git diff --cached
git commit -m "docs: finalize Mini Agent CLI v0.1 handoff and architecture review"
```

`git add logging_demo.py` 暂存其删除；明确列出路径避免混入用户数据。新增文档在暂存前不显示于普通 git diff，需单独阅读，暂存后再次检查。是否推送与创建版本标签由用户另行决定。
